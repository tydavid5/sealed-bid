## What was built

Sealed Bid, a sealed bid auction web app. Create an auction, submit one encrypted bid in demo mode, show the bid as ciphertext, close the auction, decrypt and reveal the winner, and prove a bid cannot be read before close.

- Real ML-KEM-1024 encryption through QoreSeal 0.1.0, mode `mlkem`, purpose `sealed-bid`, chain `qorechain-diana`. Nothing was substituted. No placeholder encryption.
- Real ML-DSA-87 key binding through QoreSign 0.1.0. The binding text names the chain, the auction, the bidder address and the SHA3-256 of the ML-KEM-1024 key, and it is verified before every seal.
- Registered recipient keys: the app builds the `MsgRegisterKEMKey` registry message, type URL `/qorechain.pqc.v1.MsgRegisterKEMKey`, algorithm id 2. Built and shown, not broadcast, because broadcasting needs Five's wallet.
- Client side encryption and decryption, all in the browser. Keys are generated in the browser and held in memory only.
- Deep navy with soft gold styling, sealed envelope mark, ciphertext shown as a sealed card. Layout is original to this project.
- Featured image `featured.png`, 1600 by 900 PNG, 53,578 bytes, generated by `scripts/featured-image.py`.

## What the kits did, and what failed

- `npx create-qorechain-dapp` CLI 0.14.0 worked. Scaffolded the `fullstack-web` template, TypeScript, with `npm install @qorechain/sdk` version 0.14.0.
- `@qorechain/qoreseal` 0.1.0 installed from npm and works. Its API was read from the published package before use.
- `qorechain-pqc`, the bare name from the brief, does not exist on npm. `npm view qorechain-pqc` returns 404. The published name is `@qorechain/pqc` 0.2.3, which is what QoreSeal itself depends on. That package is installed and used.
- Node's built in crypto does not offer ML-KEM here. `crypto.generateKeySync('ml-kem-1024', {})` fails with an unsupported key type on Node v24.22.1. QoreSeal's ML-KEM-1024 implementation, built on `@noble/post-quantum`, is the real ML-KEM-1024 used instead. That is the kit, not a fallback.
- Two small integration fixes during testing, both in our own code, not in the kits: the BIP-39 English wordlist is imported from `@scure/bip39/wordlists/english.js` as `wordlist`, and hex encoding uses `hex.encode` from `@scure/base` v2. Both are recorded here so the next project does not repeat them.
